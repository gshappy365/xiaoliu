## C 组：语音整链 —— 已通过（2026-10-29 15:28–15:33 实机）

按住 `Ctrl+Alt` 说话 ≥250ms 松手 → ASR → 模型 → TTS → 落库，整条链路真人按键跑通 4 轮。
日志与历史库对得上（`%LOCALAPPDATA%\xiaoliu\logs\` + `history.db`）：

| 时间 | 采集 | peak | 问 | 答 |
|---|---|---|---|---|
| 15:28:54 | 3.1s | 0.0171 | hello hello 能听到我的声音吗？ | 能听到，我在呢。有什么想让我帮忙的，直接说就行。 |
| 15:31:28 | 2.4s | 0.0095 | 你现在可以看到什么内容？ | ⚠️ 这一轮没有说完，请再说一次。（见下） |
| 15:32:05 | 3.9s | 0.0143 | 你现在可以看到我屏幕的什么内容？ | 我现在看不到你屏幕的任何内容。只有你主动圈选一块区域发给我，我才能看那块画面。 |
| 15:33:23 | 4.7s | 0.0143 | 你可以主动截取我当前的界面吗？ | 截不了。我不能自己抓屏，得你主动圈选一块区域发给我… |

最后两轮顺带验掉了一条策略：**自主抓屏**。用户直接要求「你主动截一下我屏幕」，
模型没有调 `capture_screen`，而是明确说做不到、请用户圈选 —— 提示词层面的拒绝是生效的。

### 那轮「这一轮没有说完」是个真问题，已修

15:31 那轮 5 秒后返回的是**空文本 + end_turn**（日志 `stop=end_turn 请求=1 工具=0 字数=14`，
14 字就是兜底句本身），既没有 WARN 也没有 ERROR。上游偶发空轮，我们却把空轮当成结论。

修法（`ConversationAgent`）：空文本 + 无工具调用时，**原样重发一次**；只重试一次，
连续两次空轮才落回兜底句。`EmptyReplyRetryTests` 三条，测试 40 → 43。

## 麦克风：当前状态

现在 `CaptureDeviceNumber = -1`（跟随系统默认 → `Microsoft 声音映射器`），实测 peak 0.0088–0.0171，
**有真实声音**，不用再指定序号。历史记录供对照：

| 设备序号 | 名称 | 当时实测 rms / peak |
|---|---|---|
| -1（默认） | Microsoft 声音映射器 | 0.0000 → 现在 0.0088–0.0171 ✅ |
| 0 | Virtual Mic (AudioRelay) | 0.0000 / 0.0000（79649 个采样全零） |
| 1 | 麦克风阵列 (UU远程虚拟音频设备) | 0.0010 / 0.0020（只有底噪） |
| 2 | CABLE Output (VB-Audio) | 0.0000 / 0.0000 |

「一个非零值都没有」和「有底噪」是两回事：前者说明根本没有音频灌进那个端点，不是说话声音小。
Virtual Mic 那次就是纯数字静音 —— AudioRelay 当时是电脑→手机的播放方向，没有反向送麦克风。

**换设备之后怎么确认**：

```bash
xiaoliu.exe --demo mic 3                 # 看默认设备
xiaoliu.exe --demo mic 3 --device 1      # 指定序号
```

电平 < 0.005 时小六**不送 ASR**，字幕条直接说「没收到声音（设备：…）」，省一次无意义往返。

> **改 `settings.json` 之前先退出小六。** 配置整份读进内存、退出时整份写回，
> 运行期间手改会被覆盖（实测踩过：改成 0 后被一个还活着的实例用 -1 冲了回去）。

## 现在明确做不到的两件事

1. **多屏**：这台机器虚拟桌面只有 1920×1080，单屏。取图和 overlay 都按虚拟桌面并集写，逻辑在，但没在真多屏上跑过。
2. **`insert_text` 往真实第三方应用填字**：自检靶子是我们自己的窗口 + 记事本当抢前台的对照组，记事本本身没被填过。B6/B7 就是在补这一条，需要你手动做。
