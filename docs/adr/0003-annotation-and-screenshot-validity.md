# 截图按内容指纹判活，指点图形长存活

## Context

点点给截图设 45 秒有效期，过期就拒掉指点调用（`capture_expired`）。它踩过的坑写在 `rea/reports/tool-call-drop-20261028.md`：模型想得越久，截图越容易过期，被拒之后又重截又超时，正反馈到整轮卡死。

另一头是图形：点点的标注存活很短，模型还在念的时候图形已经消失，用户看到的是「它说画好了，屏幕上什么都没有」。

## Decision

**截图有效性看内容，不看时间**：抓图时留一份 32×32 灰度指纹，指点调用时重看一眼那块区域，差异超过 8% 的格子才判 `stale_capture`。截图跨轮保留，过时的自动丢弃。

**指点图形长存活**：新图形叠加在旧图形上，不清旧的；下一轮对话开始或按 Esc 才整层清空。

## Considered Options

- **保留 45 秒定时**：简单，但它把「模型慢」惩罚到用户头上，而且和「用户盯着不动的界面连问三句」这个真实场景直接冲突。
- **逐字节比较截图**：更严格，但我们自己的字幕条和指点图形就画在屏幕上，第二次指点必然判 stale —— 实测就是这么撞上的。
- **8% 容差 vs 更大容差**：光标闪烁、时钟秒数、一行字幕大约在 3–5% 量级；换页面是 50% 以上。8% 两头都留了余量。

## Consequences

- 用户换了个窗口但画面恰好很像（同一个应用的另一个标签页），可能被判「没变」。此时指点会落在语义上不对的位置 —— 但坐标本来就来自那张图，误差不会放大。
- 指纹存在内存里，不进库；进程重启后旧截图引用一律失效。
- 图形不清旧的，意味着连续讲解会越堆越多。这是刻意的：用户需要对照「它刚才说的第一处」。
