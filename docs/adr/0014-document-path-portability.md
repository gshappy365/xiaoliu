# 文档路径可移植：绝对路径只留一张对照表

> **状态（2026-11-05）**：本决策处理 ADR 0013 盘点出的 C4 —— 文档用绝对路径交叉引用。

## Context

ADR 0013 把点点的闭源源码搬出了仓库，也把服务器启动器搬回了服务器项目。
**物理目录**上的耦合解开了，但**文字里**还留着同一根绳子。

盘点时，仓库里有 6 个文件写着 `D:\gao\wbai\rea\...`：

| 文件 | 指向 |
|---|---|
| `CONTEXT.md` | 服务器端的术语表 |
| `docs/adr/0008` | 服务器端的模型路由 ADR |
| `docs/adr/0012` | 三套工程的位置表、副本表 |
| `docs/adr/0013` | 搬家的目标位置 |
| `reference/README.md` | 点点源码的新位置、服务器端的裁剪版 |
| `reports/*` | 仓库路径、服务端的启动命令 |

另有 4 处**代码注释**指向 `rea/server/app/*.py` —— 那是服务器端项目的源码，
读代码的人会想知道「那是哪个文件」，但仓库里没有这个文件。

### 为什么这是问题

1. **换机器就失效。** 仓库在 GitHub 上是**公开仓库**。
   任何人克隆下来按文档找 `D:\gao\wbai\rea`，只会扑空 —— 那是**这台机器**的布局，
   不是项目的事实。
2. **它把耦合从文件系统搬回了文字。** ADR 0013 花了大力气让本仓库不寄生在
   别人目录里，结果文档满篇指着那个绝对路径 —— 物理上不依赖了，文字上还依赖着。
3. **漏一处就断链，而且没人会发现。** 绝对路径散落在 6 个文件里，
   改一次要动 6 处。漏掉任何一处，那条引用就静默失效 —— 没有编译错误，
   没有测试失败，只有「文档说不清了」。这是最贵的一种失效。

### 一个具体的痛

`docs/adr/0012` 的副本表里写着 `D:\gao\xiaoliu\mattpocock`。
但真名 `mattpocock` 只是**第三份副本**的目录名 —— 第一份叫 `xiaoliu-dsh`，
第二份叫 `potepo`。把「恰好在这台机器上叫这个名字」写进项目文档，
本身就说明这层信息不属于文档。

## Decision

### 1. 引入逻辑路径，绝对路径收进一张对照表

外部项目一律用**逻辑路径**指代：

| 逻辑路径 | 指什么 |
|---|---|
| `rea/` | 点点服务器端项目 |
| `rea/decompiled/`、`rea/decompiled-089/` | 服务器端项目里的点点裁剪版反编译 |
| `diandian-reference/` | 点点客户端完整反编译 |
| `diandian-server-ops/` | 服务器端运维脚本 |
| `xiaoliu-deploy/` | 小六客户端启动脚本 |
| `xiaoliu-repo/`（及其 `/potepo/`、`/xiaoliu-dsh/`） | 本仓库的三个副本 |
| `diandian-client/` | 点点客户端安装目录 |

**唯一**允许出现盘符绝对路径的地方，是新建的 `docs/workspace-layout.md` ——
它是那张对照表，把逻辑路径映射到本机实际位置。换机器时只改那一张表。

### 2. 引用一律写成「逻辑路径 + 项目内相对路径」

```
rea/server/app/main.py               ✓
diandian-reference/tools-from-diandian.json  ✓
src/Xiaoliu.Core/Protocol/SseReader.cs      ✓ （本仓库内的文件，照旧）
D:\gao\wbai\rea\server\app\main.py          ✗
```

指向本仓库自己的文件仍用仓库内相对路径 —— 这部分一直是对的，不用动。

### 3. 终端命令例外，但命令写在运维文档里

命令示例必须**能直接粘贴执行**，所以不能写成逻辑路径。
这类命令集中放在 `diandian-server-ops/README.md`，
其余文档**引用**它，不重复粘贴。

### 4. 加一条测试，把规则变成闸门

`tests/Xiaoliu.Core.Tests/WorkspacePathTests.cs` 扫描仓库里所有
`.md` / `.cs` / `.sh` / `.bat` / `.ps1` / `.py` / `.json`，发现盘符绝对路径就失败。

三条断言：

1. **除对照表外没有盘符绝对路径** —— 主规则。
2. **对照表登记了被引用的逻辑路径** —— 防止对照表被删了、或漏登记某个逻辑名，
   导致引用指向虚空。
3. **引用 `rea/` 的文件都指了路** —— 光把路径改成逻辑名不够，
   读者不知道 `rea/` 是哪，仍然扑空。所以每个引用它的文件都要提到对照表。

豁免两类：`docs/workspace-layout.md` 自身（对照表就是要写绝对路径），
以及 `C:\Windows\...` 这类操作系统固定路径（不是工作区布局，换机器也在）。

第三类豁免是本 ADR 自己 —— 一份「关于绝对路径」的决策记录，
引用违规样例是它的内容，不是它的耦合。

## Considered Options

**在 README 里写一段「本机路径如下」就够了？** 不选。
那是把散落的绝对路径**集中**成一坨，但没有解决「文档里该写什么」。
下一个人写新文档时照样会顺手写下 `D:\gao\...` —— 因为他刚在这段 README 里
看到的就是这种写法。集中的是**结果**，不是**规则**。

**用环境变量代替绝对路径**（如 `%REA_ROOT%/server/app/main.py`）？ 不选。
它确实可移植，但读者得先知道这个变量在哪设、设成什么。
对「读文档找一份参考代码」这个场景，多绕一道环境变量不划算。
逻辑路径 + 一张对照表更直白：**看表、对得上、就找到了**。

**让每个项目各自在自己的仓库里声明路径？** 不选。
服务器端项目不是 git 仓库（ADR 0013 已记），没有地方放声明；
而且那等于把「路径登记」这件事复制成 N 份。

**只改文档、不加测试？** 不选。
这是本轮最关键的取舍。手工改完这次，下次有人加一行注释就可能写回绝对路径 ——
而这类回写在 review 里极难被看见（看起来只是一句注释）。
**规则必须由机器守**，否则它只是「这次整理过了」的记录，不是约束。

## Consequences

**好的一面**

- 仓库在**任何机器**上都能读懂：读到 `rea/server/app/main.py`，
  查 `docs/workspace-layout.md` 就知道去哪儿找。
- 物理与文字两层都解开了 —— ADR 0013 的目标才算真正完成。
- 规则有闸门守着，不会慢慢漂回去。
- 换机器 / 改目录布局时，只动一张表。

**代价与注意事项**

- 读者多一次跳转（看到逻辑名 → 查表 → 拿到实际路径）。
  这个跳转是**故意**的：它把「这台机器的布局」和「项目的事实」在阅读时分开了。
- 对照表是本机快照 —— 它自己会过期。但它只有一处，过期了改一处，
  而不像散落的绝对路径那样过期得无声无息。
- 测试扫描的是**工作区文件**而非 git 索引，所以未提交的新文件也会被扫到 ——
  这正是想要的（写完还没提交就想跑测试）。
- `.workbuddy/` 目录被排除：那是 WorkBuddy 的项目记忆（本地工作日志），
  记录当时的操作位置属正常，不属于「项目文档的交叉引用」。
- `docs/adr/0013` 里 `D:\gao\wbai\xiaoliu\` 这类「被搬走的旧位置」也改成了
  逻辑名。理由一致：那也是这台机器的布局，不是项目事实。
  搬家记录本身（搬了什么、为什么搬）一个字没少。

## 验证

- 改造前全仓扫描：6 个文档文件 + 4 处代码注释含绝对路径
- 改造后：除 `docs/workspace-layout.md` 外，**零**盘符绝对路径
  （`C:\Windows\...` 属操作系统固定路径，已豁免）
- `docs/workspace-layout.md` 里登记的 9 个逻辑路径全部经文件系统核实存在
- 负向验证：故意放一个含盘符路径的探针文件，测试**准确报错并指出文件名与行号**；
  探针已删除
- Release 构建 0 警告 0 错误；116 个单测全绿（原 113 + 新增 3）
