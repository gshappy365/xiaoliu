# 界面对齐点点的交互形态：气泡跟着指点走，顶部留常驻胶囊

## Context

v1 的界面只有一条 760 宽的顶部字幕条 + 托盘图标。功能上够用，但和点点摆在一起时是两种产品：

| | 点点 | v1 |
|---|---|---|
| 常驻形态 | 顶部居中小胶囊（圆点 + 名字） | 屏幕上什么都没有，只有托盘图标 |
| 回答气泡 | 320×96，跟着指点目标浮动 | 760 宽，固定顶部居中 |
| 指点图形 | 软边发光光环（外 44 / 内 31 / 软边 1.5） | 3px 细圆环 + 浅蓝方框 |

差得最狠的不是配色，是**回答出现在哪里**：点点把答案放在它指的东西旁边，v1 永远放在屏幕顶上 —— 用户得在「被指的位置」和「屏幕顶部」之间来回看。

## Decision

按点点的交互范式重做，但不复制它的素材、配色和角色形象：

- **顶部常驻胶囊**：一个 26 高的小胶囊，圆点呼吸 + 「小柳」，状态文字（在听 / 在想）跟着变。点一下打开历史窗。
- **回答气泡**：宽 320，高度 96 起、最多 176；锚定规则照点点的 `AnswerBubbleWindow` —— 水平居中于目标、目标下方 52 DIP、越界夹回屏幕工作区。没有指点目标时贴在胶囊下方。
- **指点图形**：点改成软边光环（88 外径、13 环宽、5 模糊），区域框降到 2px 边 + 0x16 填充 + 圆角 10，标签去描边。

## Considered Options

- **只调配色圆角，布局不动**：改动小，但「答案跟不跟指点走」这个核心差别不解决。
- **完全照抄点点（含角色形象与渐变材质）**：视觉最接近，但那是别人的素材与品牌，不该抄；而且我们没有人力和它做像素级对齐。
- **气泡固定 96 高**：点点是这么做的，因为它还有一张卡片承载全文。我们没有卡片，96 高只能放三行，长回答会被截断 —— 所以留到 176 的上限，短回答仍是 96 的形态。

## Consequences

- 长回答仍然会被截断（三行到七行之间），全文在历史窗里看。要彻底解决得加「点气泡展开」的卡片，属于 v2。
- 胶囊和气泡都是点击穿透 / 不抢焦点的窗口，点胶囊不激活也不进 Alt+Tab，用户正在打字的窗口不会被切走。
- 多屏时气泡的夹取用的是主屏工作区（`SystemParameters.WorkArea`），目标在副屏上会夹得偏保守。这台机器只有一块屏，没在真多屏上验过。
