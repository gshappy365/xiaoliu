# 改名小六，主界面改成从顶部胶囊悬停展开

## Context

界面按点点复刻完之后，摆在一起对比仍然有两个不像：

1. **名字**：产品叫「小柳」，但交付的 exe 一直是 `xiaoliu.exe`、命名空间是 `Xiaoliu`。
   用户要改成「小六」—— 拼音正好也是 xiàoliù，和代码里的标识符对得上。
2. **主界面的出现方式**：点点平时只在屏幕正上方留一个小入口，**鼠标移上去才展开面板**；
   小六是点一下弹一个 1000×680 的独立窗口，还要抢焦点。用户原话：
   「为什么没有做成点点那样，是在屏幕中央上方，鼠标过去界面才显示出来」。

第 2 条不只是"像不像"的问题。点击打开的大窗口会**抢走焦点** —— 用户正在别的程序里打字，
点一下胶囊去查历史，正在打的字就断了。悬停展开则不激活窗口，看一眼就能走。

## Decision

**改名只改用户可见的文案**：界面标题、托盘提示、气泡说话人、提示词里的角色名、日志。
程序集名 `xiaoliu`、命名空间 `Xiaoliu.*`、配置目录 `%LOCALAPPDATA%\xiaoliu`、
互斥锁名都不动 —— 拼音一致，改了只是增加 diff 和迁移成本，用户看不见。

**主界面改成胶囊下面的一块面板**：

- `WorkspaceWindow` 加 `Topmost` + `ShowActivated="False"`，位置固定在胶囊下沿 +6 DIP、水平居中
- `PillWindow` 加 `Hovered` 事件；鼠标进入胶囊时触发，面板从上方 12 DIP 滑入 + 淡入（220ms）
- 收起靠 `DispatcherTimer` 每 180ms 轮询 `GetCursorPos` + `GetWindowRect`：鼠标既不在面板
  （8px 容差）也不在胶囊上，连续 4 轮（约 720ms）才淡出收起
- **不自动收起的情况**：面板被点进去（`IsActive`）—— 用户在里面打字/翻设置，鼠标滑出去不该消失
- 点胶囊 = 钉住；已钉住的再点 = 收起；`Esc` 也收起
- 从托盘菜单/双击图标打开 = 直接钉住（用户是主动叫的，不该自己跑掉）

## Considered Options

- **只把窗口改成贴顶部，交互仍靠点击**：改动最小，但用户要的就是「鼠标过去自己出来」，
  这个不改等于没做。
- **用 `IsMouseOver` 判断要不要收起**：WPF 的 `IsMouseOver` 只在窗口自己收到鼠标消息时更新，
  鼠标移到别的程序上就停在最后一次的值 —— 靠它判断永远收不起来。必须查系统光标位置。
- **胶囊展开时隐藏**：面板占住顶部后胶囊没地方站，但隐藏会带来「鼠标从面板滑到胶囊位置 →
  面板收起 → 胶囊出现 → 又触发悬停展开」的抖动。让胶囊常驻、面板从它下面长出来更稳。
- **面板不激活（`WS_EX_NOACTIVATE`）**：这样连点都点不进去，输入框没法打字。
  用 `ShowActivated=False` 只保证"出现时不抢焦点"，点进去仍能正常激活。

## Consequences

- 面板展开时**不抢焦点**，代价是首次展开后要再点一下才能打字。这是刻意的：
  「看一眼」是这个界面的主用法，打断用户正在输入的成本更高。
- 收起靠 180ms 轮询，有最多 0.9 秒的延迟（4 轮 × 180ms + 淡出 140ms）。够用，但比事件驱动的
  `WM_MOUSELEAVE` 粗糙。真嫌慢可以改成在面板上挂 `MouseLeave` + 全局钩子，复杂度上一个台阶。
- 面板贴着屏幕顶部，**多屏/高缩放没验过**：`SystemParameters.WorkArea` 只给主屏，
  副屏上悬停展开会跑到主屏顶部。这台机器只有一块屏。
- 标题栏不再写「小六」（胶囊上已经有名字），改成显示当前页面名「对话/历史/设置」，
  否则一个界面上会出现两个「小六」。最小化按钮删掉 —— 面板的"最小化"就是收起，和关闭重复。
