# 模型下拉的候选写死在客户端，服务端按前缀选上游

## Context

设置页「模型」原来是一个自由文本框：用户能填任何字符串，填错了只有等上游报错才知道。
要改成下拉，就得回答「候选从哪来」。

用户要求：「读取 ark-cli 里的可用大模型，配置到 设置-模型界面大模型的下拉可选项」，
随后追加：「我在客户端选定哪个大模型，然后服务器端需要同步更新。点点旧配置里的
大模型不需要了。」

后半句是硬要求。原来服务端 `rewrite_request` 无条件把 `model` 覆盖成 `UPSTREAM_MODEL`，
所以「界面选了 A、实际用 B」是必然结果 —— 下拉做出来也是假的。服务端为此改了路由
（`D:\gao\wbai\rea\docs\adr\0006-client-selected-model-routing.md`），
按客户端发来的 model 前缀决定走方舟还是默认上游。

## Decision

- **候选写死成快照**：`Xiaoliu.Core/Configuration/ModelCatalog.cs`，来源是
  `arkcli models list --format json --page-all`（54 个），按 `task_types` 含
  `text_generation` 过滤出 23 个能当对话模型用的。文件头写了怎么重新生成。
- **不做运行时调用 arkcli**：单文件 exe 不能假设用户机器上装了 arkcli、还登着账号；
  真去调还会把启动路径变成「依赖外部 CLI」。
- **分两组，视觉组在前**：`Vision`（10 个，能看懂截屏）与 `TextOnly`（13 个）。
  小六的核心能力是看屏幕，纯文本模型圈选/截图类提问会直接失效，所以下拉里用
  `IsEnabled=false` 的分组标题把这件事写在界面上。
- **删掉点点协议名（`aliyun.*` / `volcengine.*`）那 9 个**：服务端已按前缀路由，
  旧名字不再需要；留着只会让用户选到一个「服务端不认识、悄悄落到默认上游」的 id。
- **选择器是不可编辑的 `ComboBox`**：自绘模板（`PickerStyle`）不支持 `IsEditable`
  —— 没有 `PART_EditableTextBox`。要用可编辑下拉就得重写模板，不值得。
- 配置里的值不在清单里时，临时插一项「xxx（当前配置）」，不静默改用户的配置。

## Considered Options

- **运行时调 arkcli 拉清单**：清单永远最新，但把「启动就能用」变成「得先装 arkcli 并登录」，
  与单文件交付矛盾。
- **从服务端要一份清单**：多一个协议端点，且服务端与方舟账号绑定，客户端换服务端就失效。
- **保留自由文本框 + 校验**：校验只能挡住拼写错误，挡不住「这个 id 服务端不认识」。
- **让服务端维护 id → 上游映射表**：表会和 `ModelCatalog` 漂移，两边都得改；
  前缀判据是唯一「客户端加模型不用改服务端」的写法。

## Consequences

- 清单会过期。方舟上下架模型后，下拉里会出现调不通的项 —— 重新生成的办法写在
  `ModelCatalog.cs` 文件头。这是拿「零运行时依赖」换来的确定代价。
- 前缀是启发式的：方舟将来出个新前缀（比如 `seed-`）会被服务端静默发到默认上游。
  所以 `ModelCatalogTests` 里钉了一条「每个 id 的前缀服务端都认识」——
  这类错误在界面上完全看不出来。
- 换模型**下一轮生效**，不是立刻：当前轮的工具回环已经带着旧模型跑起来了。
- 选纯文本模型时圈选/截图失效，这是能力差异不是 bug，下拉里已标注。
- 实测延迟（走 CLI，同一句问题）：`spark-x2.6` 首字 12154ms / 总 12649ms；
  `doubao-seed-2-1-pro` 首字 1045ms / 总 1921ms。默认值因此改成了方舟视觉旗舰
  `doubao-seed-2-1-pro-260915`。
