# 留存默认 90 天 / 7 天 / 200MB，超限先删图

## Context

本地库是明文 SQLite，里面唯一的高价值泄露物是截图 —— 文本丢了可以重问，屏幕内容流出去就收不回来。点点用「90 天 + 200MB」一个阈值管全部。

## Decision

三个独立参数：文本留 90 天、图片留 7 天、总量兜底 200MB。超限时先删最旧的图片，图片删完还不够再删最旧的文本。三个参数都能被 `update_setting` 改。

## Considered Options

- **照抄点点的单一阈值**：简单，但「文本」和「图片」的风险根本不同级，用同一个数就是把图片的风险绑在文本的便利上。
- **默认不存图片**：最安全，但 `search_history` 和「回看上次那张图」就废了，而 ADR 0005 明确要保留历史查看窗。

## Consequences

- 七天前的历史还在，但对应的截图已经没了。历史窗里的「截图 N 张」会显示 0，这是预期行为，不是 bug。
- 200MB 是兜底不是目标：按 1280/q75 约 100KB 一张算，200MB 能装 2000 张，实际先撞到的是 7 天那条线。
- 清理在启动时跑一次。常驻进程不会在跑着的时候清理 —— 用户可能正在看历史窗。
